# 🌾 ImGround

**3D 농장 시뮬레이션 RPG**

- **개발 인원**: 6인 팀 프로젝트
- **담당 역할**: 플레이어 상호작용 및 동작 구현, 작물 성장 로직, 몬스터 AI
- **개발 기간**: 2024.07 ~ 2024.12
- **사용 기술**: Unity, C#

> 💡 **안내**
> 이 디렉토리는 팀 프로젝트에서 제가 직접 작성한 스크립트만을 발췌한 것입니다. 
> 원본 프로젝트는 팀 조직 저장소에 있으나 접근 권한이 필요하여, 포트폴리오 리뷰를 위해 담당 코드만 별도로 분리했습니다.

<br>

## 🎯 핵심 구현 사항

### 1. 컴포넌트 기반 플레이어 아키텍처 설계 (Separation of Concerns)
- **설계**: `Player` 단일 객체의 코드가 비대해지는 현상(God Class)을 방지하기 위해 이동(`PlayerMove`), 공격(`PlayerAttack`), 상호작용(`PlayerBehavior`), 건축(`PlayerBuild`) 기능을 독립된 컴포넌트로 분리했습니다.
- **효과**: 각 기능 간의 결합도를 낮추고 단일 책임 원칙을 준수하여, 추후 기능 확장 및 유지보수가 용이한 구조를 확립했습니다.

### 2. ScriptableObject 기반 데이터 주도(Data-Driven) 농사 시스템
- **설계**: 작물의 성장 단계와 소요 시간 등 잦은 변경이 예상되는 기획 데이터를 `CropData` ScriptableObject로 에셋화하여 관리하도록 구현했습니다.
- **효과**: 코드 내 하드코딩을 배제하고 데이터와 로직을 완벽히 분리함으로써, 기획자가 프로그래머의 개입 없이도 독립적으로 콘텐츠를 추가하고 밸런스를 조정할 수 있는 효율적인 파이프라인을 구축했습니다.

### 3. 하이브리드 데이터 세이브 구조 (PlayerPrefs + JsonUtility)
- **이슈**: `PlayerPrefs`가 기본적으로 int, float, string 타입만 지원하여 `Vector3`와 같은 복합 구조체(위치 정보 등)를 저장하는 데 제약이 있었습니다.
- **해결**: 복잡한 구조체 데이터는 `JsonUtility`를 활용해 JSON 포맷으로 직렬화(Serialization)하여 저장하고, 단순 수치 및 문자열 데이터는 `PlayerPrefs`를 사용하는 하이브리드 방식을 채택하여 세이브 시스템을 유연하게 구현했습니다.

## 📁 주요 스크립트

| 파일명 | 주요 역할 및 기능 |
| --- | --- |
| `Player.cs` | 플레이어의 핵심 스탯 데이터 관리 및 직렬화 기반 저장/로드 로직 |
| `PlayerBehavior.cs` | 농기구/무기 등 도구 사용 및 환경 상호작용 이벤트 총괄 |
| `PlayerBuild.cs` | 건축물 배치 프리뷰 시스템 및 실제 인게임 타일 기반 배치 로직 |
| `Enemy.cs` / `Boss.cs` | 상태 기반 일반 몬스터 AI 및 보스 페이즈별 공격 패턴 구현 |
| `Crops.cs` / `CropData.cs` | 시간에 따른 작물 상태 전이 로직 및 데이터 에셋(SO) 연동 시스템 |
